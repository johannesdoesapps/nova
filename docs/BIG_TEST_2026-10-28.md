## Browser sweep — what the remaining console messages are

None are product bugs:

- `/_vercel/insights/script.js` 404 + MIME error on every page: Vercel Analytics only exists on Vercel.
- `/admin` and `/agents/directory` 500s on `/api/admin/{finance,unit-economics,product,diagnostics}`: the local mock
  database doesn't implement those reporting functions (it answers "function not found"); they are defined in the
  real migrations.
- `/share/<bad token>` 503: the separate engine service isn't configured locally.
- `/jarvis` connection refused: a local connection attempt that fails because the optional Orbis Desktop Agent isn't running here (expected).
- axe notes on `/share/badtoken` and `/research-print/...` (no `<main>`/`<h1>` on the error and print views): minor,
  left as is.

## Not fixed — need your decision or are low priority

1. **Pricing (P10, business decision).** With the $5/$35 minimum budgets, part of the 15% safety buffer is used:
   Pro's buffer drops from $0.85 to $0.70 a month, Max's from $5.95 to $4.69. Every scenario still meets the 65%
   margin (tests check this). Keeping the full buffer would need **$28.60 Pro / $157.85 Max**.
2. Orchestrator: if the `attempt_state` lookup itself errors, the executor continues instead of stopping (fails
   open); retired sub-tasks don't go through `orch_resolve_dependents`. Both need a database error or an unusual
   state to matter.
3. `kickWorker` builds the worker URL from the request's origin. Vercel sets the host, so it isn't exploitable as
   deployed, but a fixed `ORBIS_SITE_URL` would be sturdier.
4. Parallel helper agents share one usage ticket (accounting is right in total, less precise per helper).
5. A PR comment can be posted twice if two audits finish at the same moment; preventing it needs a unique index
   (migration).
6. `usage_finish` lets a user release their own usage hold early; it only affects that user's own allowance.
7. Supabase leaked-password protection is off (Auth setting; turning it on is your call).
8. There are no paying subscribers in production, so the billing paths have only been exercised by tests.

This was a broad but limited test; it doesn't prove the absence of other bugs or vulnerabilities.
