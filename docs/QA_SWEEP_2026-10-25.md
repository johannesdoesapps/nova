### Details

**QA-01** — Steps: `npm audit --omit=dev` → 4 high (zod <4.6.6 via `@vercel/cli-config@0.3.1`). Expected: no known vulnerabilities. Root cause: transitive dependency pinned to zod 4.1.11. Fix: `overrides` in `package.json` (`@vercel/cli-config` → `zod ^4.6.7`) and the stale nested lock entry removed; `npm ls zod` shows it deduped to 4.6.7. Practical exposure was low (the CLI config reader isn't fed untrusted input). Regression test: `tests/qa-regressions.test.ts` (QA-01). Verification: `npm audit --omit=dev` → 0 vulnerabilities; full test suite and build pass.

**QA-02** — Steps: `POST /api/code/projects` with `{}` and no session → 400 "Invalid request" with field details; with a well-formed body → 401. Verified for chat, search, code run, images, compare, Council, code projects and team invites (all 401 with valid bodies). Impact: request-schema disclosure and a little wasted work; no access is granted. Not fixed: touches ~80 routes; worth doing as one mechanical change with tests.

**QA-03** — Evidence: Chrome DevTools issue `ContentSecurityPolicyIssue` (`kEvalViolation`, chunk `40--a87k7bgrm.js`), Lighthouse best-practices 96 on /pricing. Zod v4 tries `Function("")` inside try/catch to decide whether it can JIT; the CSP correctly blocks it and zod falls back. Harmless; fix would be `z.config({ jitless: true })` in client code.

**QA-04** — Reproduced with axe at 390 px on /agents/directory and /admin. Fix: `tabIndex={0} role="region" aria-label=…` on every `overflow-x-auto` wrapper around a `<table>` (11 places). Regression test scans all components (mutation-checked: reverting one fix fails the test). Verified: axe re-run on the affected routes at 390 and 1366 px → no violations.

**QA-05** — `#8c8c8c` on white at 10.5 px. Fix: `text-black/45` → `text-black/60` (≈5.7:1). Verified with axe.

**QA-06** — Two suggested fixes in the same file produced two regions named "Changes to <file> (suggested, not applied)". Fix: include the line (`file:line`). Verified with axe on the seeded review.

**QA-07** — e.g. `/research/<missing id>` shows "Research not found." with a back link in the header bar, but no `<h1>`. Minor screen-reader orientation issue.

**QA-10** — `next.config.ts` redirects the legacy routes (including `/settings/:path*`, which also matches `/settings`). This is intentional — settings live in a dialog in the current app — and no visible link in the current UI points to them; the leftovers are dead code.

### Investigated, not bugs

- `/settings` → `/chat`: intentional legacy redirect (QA-10); Settings is a dialog (command palette, account menu).
- Production `/chat` didn't reach "network idle" in 45 s during the sweep: re-tested with `load` — 200 in 1.6 s, no requests after 4 s, no errors, clean at all widths.
- Local `/admin` finance/product cards returned 500: the mock database lacks those functions; all four (`admin_finance_summary_v3`, `admin_product_metrics`, `admin_code_funnel`, `admin_onboarding_funnel`) exist in production.
- `/_vercel/insights/script.js` 404 locally: only served on Vercel.
- `/login` SEO 66 in Lighthouse: deliberate `noindex`.
- "Skip to content" flagged as a small target: it's visually hidden until focused.
